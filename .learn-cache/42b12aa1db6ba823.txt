What's new in Agent 365 - September 2026
https://techcommunity.microsoft.com/t5/agent-365-blog/what-s-new-in-agent-365-september-2026/ba-p/4560803
<P>Since launching Agent 365 in May 2026, nearly 50 million agents have been registered across tens of thousands of organizations. As agent adoption accelerates, IT and security teams are looking beyond simple visibility and governance to a new challenge: understanding which agents are delivering value, where resources are being spent, and how to optimize a growing agent estate at scale.</P>
<P>This month’s Agent 365 updates help address these challenges with new capabilities that connect AI workloads to business outcomes, provide more visibility and control across the agent estate, and centralize governance across agents, tools, and runtime environments. Together, these enhancements help organizations reduce blind spots, automate oversight, and scale AI investments with confidence.</P>
<H2>Connect AI workloads to business value</H2>
<P>As AI usage grows across agents, applications, and services, organizations need one place to manage consumption and align access with business needs. Cost management in Agent 365 delivers FinOps for AI capabilities to help organizations manage usage-based AI spend, set clear spending guardrails, track costs and connect usage to value. Cost management in Agent 365 is included with Microsoft cloud subscriptions. New innovations include:</P>
<H3>Manage more usage-based billed workloads in one place</H3>
<P>Cost management in Agent 365 expands beyond Copilot Cowork and WorkIQ and now supports Code and Copilot Managed Runtime. Support for agents built with Microsoft Copilot Studio is planned for October, with more AI workloads to follow, making Agent 365 the central home for managing usage-based billing.</P>
<img />
<H3>Match model choice to business needs</H3>
<P>When configuring a spending policy in cost management, admins can give different groups access to the models and effort levels that best fit their work. These policies also shape which models Auto can select in Cowork, allowing advanced models for high-impact projects and power users while offering more efficient options elsewhere. The capability is rolling out for Cowork, with additional workloads planned.</P>
<img />
<H3>Connect consumption to Cowork value</H3>
<P>The Consumption Dashboard in Insights connects Copilot Cowork usage with outcomes, showing trends across active users, credits, and tasks; organizing work by task category; and estimating Cowork-assisted value in time and dollars.</P>
<P>Leaders can compare value-generating tasks with the credits they consume to decide where to expand adoption, improve usage, or redirect investment.</P>
<img />
<H2>Gain more visibility and control across the agent estate</H2>
<P>As agent estates grow across platforms, IT needs a complete inventory and faster ways to identify where action is required. Agent 365 brings Microsoft-native and third-party agents into one registry, then helps administrators turn that visibility into action through intelligent discovery and automated governance. New innovations include:</P>
<H3>Find the agents that need attention with AI mode</H3>
<P>As registries grow, finding the right agents should not require building complex filters. Now in public preview, AI mode transforms the Agent 365 registry from a static browsing experience into an intelligent discovery experience. Administrators can use natural-language prompts to find, filter, and explore agents using contextual attributes - for example, to identify agents without owners, locate inactive agents, or surface agents that warrant closer review. This reduces time to insight and helps administrators turn registry data into practical governance workflows.</P>
<img />
<H3>Drive consistency, efficiency, and scale for agent management with automated rules</H3>
<P>Agent Management Rules, now available in public preview, give admins a powerful way to automate agent governance at scale. In the Microsoft 365 admin center, admins can create custom rules to automatically take actions such as blocking agents, rejecting publication requests, or applying policy templates when specified conditions are met. Rules can be based on a growing set of criteria, including ownership status, agent tags, Microsoft Entra Agent ID, publisher, risk signals, usage activity, and more. This helps organizations reduce manual administration, enforce governance consistently, and keep their agent inventory secure, compliant, and well managed as agent adoption grows.</P>
<img />
<H2>Centralize governance across agents, tools and runtimes</H2>
<P>As agents gain access to more tools, data, and services, organizations need consistent controls that extend across the full agent ecosystem. Agent 365 centralizes governance across agents, tools, and runtime environments, helping IT reduce fragmented oversight, enforce policy consistently, and protect enterprise resources as adoption grows. New innovations include:</P>
<H3>Control MCP servers, plugins, skills, and connectors from one place</H3>
<P>Now generally available, Tools management in Agent 365 expands the centralized governance experience beyond MCP servers to include plugins, skills, and connectors. Plugins provide reusable actions and integrations, skills add specialized AI capabilities and workflows, and connectors enable secure access to enterprise and third-party data and services.</P>
<P>From one management pane, administrators can discover connected tools, review key metadata and usage, and apply tenant-wide allow or block controls across MCP servers, plugins, skills, and connectors. This consistent framework reduces the need to manage tools across separate systems and helps keep agent access within approved organizational boundaries. Power Platform connectors governance is in progress.</P>
<img />
<H3>Put custom MCP servers on an approval path</H3>
<P>Organizations can also bring their own MCP servers under explicit IT oversight. In public preview in September 2026, developers can register custom MCP servers through the Agent 365 CLI and submit them for administrator review before agents are allowed to invoke them. In the Microsoft 365 admin center, administrators can inspect the server description, publisher, requestor, endpoint, and capabilities, then approve or reject the request.</P>
<P>This creates a clear path from extension to approval. Customers and partners can add the custom and third-party MCP servers their work requires, while IT maintains visibility and control across agents operating in the Microsoft 365 tenant.</P>
<H3>Connect enterprise AI governance with runtime policy enforcement</H3>
<P>Beginning September 30, the integration between Microsoft Agent 365 and Azure API Management will begin rolling out, connecting centralized AI governance with policy enforcement at runtime. AI assets onboarded to Azure API Management, including agents, tools, models, and MCP servers, can be automatically discovered in Agent 365, improving visibility while reducing manual onboarding. Administrators can centrally govern access through Agent 365, while Azure API Management applies authentication, routing, and runtime controls to help protect AI traffic and enterprise assets as agents take action.</P>
<H3>Turn agent growth into business impact</H3>
<P>Organizations are entering a new phase of AI adoption. Success is no longer measured by the number of agents deployed, but by how effectively those agents are tracked, managed, and connected to business outcomes.</P>
<P>The latest Agent 365 innovations help organizations understand AI value, gain deeper visibility into their growing agent estate, and apply governance at scale. Together, these capabilities enable IT and security teams to confidently transform agent growth into measurable business impact.</P>

<H1><SPAN data-contrast="none">Bring&nbsp;predictability to&nbsp;agentic&nbsp;AI spend with Cost Management</SPAN><SPAN data-ccp-props="{}">&nbsp;</SPAN></H1>
<P><SPAN data-contrast="auto">As organizations expand their use of agents, they need clear&nbsp;controls&nbsp;to&nbsp;understand consumption, manage budgets, and keep usage-based costs predictable. Cost Management in&nbsp;the Microsoft 365 admin center&nbsp;gives admins a centralized way to&nbsp;monitor&nbsp;and control Copilot Credit spend for&nbsp;agentic&nbsp;usage-based services.&nbsp;This release focuses on&nbsp;Cowork&nbsp;and Work IQ&nbsp;spend.&nbsp;New enterprise-ready updates improve the reliability of spending alerts, make policy assignment more consistent, strengthen the handling of per-user overages, and&nbsp;provide&nbsp;a clearer view of prepaid capacity across Microsoft 365 and Power Platform admin experiences.&nbsp;When a user belongs to multiple spending policies for the same service, the applicable policy is now selected using clear criteria: the highest per-user limit, followed by the largest overall policy limit and then the most recently created policy.&nbsp;The selected policy applies in full, helping admins&nbsp;anticipate&nbsp;which billing configuration and limits will govern each user without combining settings across policies.&nbsp;The updates also help protect shared capacity when a task exceeds a user’s individual limit while it is already running. With this release, Microsoft may allow that task to finish without drawing the resulting per-user overage from the policy’s shared pool or billing it, helping preserve credits for the rest of the group.&nbsp;Finally, admins gain a more&nbsp;accurate&nbsp;picture of capacity-pack credits available for use. Cost Management will distinguish credits already consumed or&nbsp;allocated&nbsp;through other admin centers, including capacity assigned to Power Platform environments or agents, so the amount presented during spending-policy setup more closely reflects the prepaid capacity that&nbsp;remains&nbsp;available.</SPAN><SPAN data-ccp-props="{}">&nbsp;</SPAN></P>

<P><SPAN data-contrast="auto">Registry sync is now generally available in Microsoft Agent 365, giving organizations a centralized way to&nbsp;discover and&nbsp;inventory agents that exist beyond Microsoft platforms. As enterprises increasingly build and deploy agents across multiple agent development platforms,&nbsp;maintaining&nbsp;visibility becomes increasingly difficult. Registry sync addresses this challenge by allowing AI administrators to securely connect supported ecosystem agent platforms and synchronize agents and metadata into the Agent 365 registry&nbsp;on a daily or weekly cadence,&nbsp;establishing&nbsp;a single, authoritative system of record for their agent estate. With Registry sync, organizations can reduce blind&nbsp;spots&nbsp;ecosystem&nbsp;partner&nbsp;platforms by bringing externally developed agents into a unified discovery and management experience. Administrators can view synchronized agents alongside Microsoft-native agents, understand where agents originate, review key metadata, and gain a more complete picture of their growing agent landscape.&nbsp;Supported platforms at general availability include Amazon Bedrock, Google Cloud Gemini Enterprise Agent Platform,&nbsp;Anthropic Claude,&nbsp;Databricks Genie,&nbsp;Salesforce&nbsp;Agentforce. Additionally, Snowflake, Oracle OCI, and&nbsp;UIPath&nbsp;to follow soon.</SPAN><SPAN data-ccp-props="{}">&nbsp;</SPAN></P>
<P><SPAN data-contrast="auto">Registry sync goes beyond visibility. Where supported by the underlying&nbsp;platform&nbsp;APIs, administrators can take agent-level governance actions directly from Agent 365, including lifecycle management actions such as&nbsp;deleting&nbsp;synchronized agents. This enables organizations to govern agents across platforms from a common management&nbsp;plane&nbsp;while continuing to use the development and runtime environments that best fit their business needs. By extending the Agent 365 registry beyond Microsoft boundaries, Registry sync strengthens Agent 365 as the enterprise control plane for agents. Whether agents are built by Microsoft, developed internally, or created on ecosystem platforms, organizations can now&nbsp;establish&nbsp;a more comprehensive view of agents&nbsp;operating&nbsp;across their organization, helping IT and security teams&nbsp;maintain&nbsp;visibility, reduce risk, and improve governance at scale.</SPAN><SPAN data-ccp-props="{}">&nbsp;</SPAN></P>

<H1 aria-level="1"><SPAN data-contrast="none"><SPAN data-ccp-parastyle="heading 1">Manage agents across multiple tenants from one place</SPAN></SPAN><SPAN data-ccp-props="{&quot;134245418&quot;:true,&quot;134245529&quot;:true,&quot;335559738&quot;:360,&quot;335559739&quot;:80}">&nbsp;</SPAN></H1>
<P><SPAN data-contrast="auto">Partners supporting multiple customers and enterprises operating complex multi-tenant environments&nbsp;both&nbsp;need a simpler way to&nbsp;maintain&nbsp;consistent visibility and control. With multi-tenant agent management, now in public preview, administrators can centrally view and manage agents across connected tenants from the Agent 365 in the Microsoft 365 admin center.</SPAN><SPAN data-ccp-props="{}">&nbsp;</SPAN></P>
<P><SPAN data-contrast="auto">From All tenants &gt; Agents, administrators can view a&nbsp;consolidated&nbsp;agent inventory, add custom agents, deploy agents across selected tenants, compare tenant-specific availability and permissions, review agent risk and activity, and block agents or change their availability where needed. They can also use the tenant switcher to enter a connected tenant through delegated access, without&nbsp;maintaining&nbsp;a separate administrator account in that tenant. Where applicable licensing requirements are met, administrators can also review agent risks. The experience builds on existing cross-tenant administration relationships and Granular Delegated Admin Privileges (GDAP). Partners configure these relationships in Partner Center, while enterprises can configure them through Microsoft Entra Tenant Governance. Available tenants and management actions are&nbsp;determined&nbsp;by the active tenant relationship and the administrator’s delegated role.&nbsp;</SPAN><SPAN data-ccp-props="{}">&nbsp;</SPAN></P>
<P><SPAN data-contrast="auto">Multi-tenant agent management extends your existing tenant governance foundation into a centralized control plane for agent observability, governance and security. What's new in Agent 365 – June 2026
https://techcommunity.microsoft.com/t5/agent-365-blog/what-s-new-in-agent-365-june-2026/ba-p/4535107
<P><EM>By Alex Pozin, Samer Baroudi, Brendan Powers</EM></P>
<P>As AI agents become a core part of enterprise operations, organizations need a consistent way to observe, manage, govern, and secure agents across an increasingly distributed ecosystem spanning cloud, local, and partner-developed experiences. Since the&nbsp;<A href="https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-agent-365-may-2026/4516340" target="_blank" rel="noopener">GA release</A>, Agent 365 has continued to evolve as the control plane for enterprise agents. This month’s innovations strengthen visibility and protection for local agents, simplify onboarding and lifecycle management, and expand programmatic governance capabilities, helping organizations scale AI adoption with greater confidence.</P>
<H2>Visibility, controls and protections for local agents</H2>
<P>As local agents become a growing part of the enterprise AI landscape, Agent 365 is expanding end-to-end visibility, governance, and protection across these experiences. From discovering and inventorying local agents in the Agent 365 Registry, to auditing agent activity with Microsoft Purview, securing runtime behavior with Microsoft Defender, and enforcing isolated execution through Microsoft Execution Containers (MXC), organizations gain the controls needed to confidently manage, secure, and govern local agents at scale without sacrificing user productivity.</P>
<H3>Local agents in the Agent 365 registry</H3>
<P>Organizations increasingly rely on local agents running directly on user devices, yet these agents often operate outside AI visibility. With local agents now in the Agent 365 registry (public preview), IT and security teams gain a unified view of shadow local agents detected across the environment. The registry surfaces each agent's publisher, detected device count, and last scanned date, and opens into a per agent details pane that lists every endpoint where the agent has been observed, complete with device name, model, and operating system. By centralizing discovery and device‑level context for local agents across managed endpoints, teams pinpoint which shadow AI agents users are running, scope their footprint by device, and accelerate investigations.</P>
<P>&nbsp;</P>
<img />
<H3>Microsoft Purview Audit coverage for GitHub Copilot CLI, Claude Code, OpenAI Codex, and OpenClaw</H3>
<P>Microsoft Purview Audit in Agent 365 continues to expand its coverage, bringing deeper visibility into agent interactions and strengthening enterprise compliance capabilities. Building on its ability to capture and monitor audit logs across human-to-agent, agent-to-agent, and agent-to-tool interactions with rich contextual metadata on access, actions, and activity, the June update introduces support for emerging local and developer-focused agents, including GitHub Copilot CLI, Claude Code, OpenAI Codex, and OpenClaw. This expansion ensures that organizations can audit activity consistently across these local agents, closing visibility gaps as agent usage becomes more distributed. By extending familiar Microsoft Purview auditing workflows to these new agent experiences, enterprises can more effectively investigate incidents, meet compliance requirements, and confidently scale AI adoption with comprehensive, end-to-end observability.</P>
<H3>Microsoft Defender and Purview expand Agent 365 security capabilities to cover local agents (Public Preview)</H3>
<P>Microsoft Defender in Agent 365 expands security posture management, on-device runtime protection, XDR alerting, and advanced hunting for local AI agents. Since the June 2 release, Defender has expanded discovery of local agents and MCP servers across managed Windows and macOS devices, now supporting more than <A href="https://learn.microsoft.com/en-us/defender-endpoint/local-agent-discovery-overview#supported-local-ai-agents-and-mcp-server-configurations" target="_blank" rel="noopener">35 known agent types in preview</A>. With this release, Defender also introduces exposure risk for local agents, helping security teams identify and prioritize the riskiest local agents based on their configuration, permissions, and exposure, with recommendations to reduce risk.</P>
<P>Defender's on-device runtime protection capabilities, now available in public preview, support Claude Code, GitHub Copilot CLI, GitHub Copilot app, Codex CLI, OpenClaw, and similar Node-based claws using agent-native event inspection and an on-device, network-based runtime inspection. Defender can audit or block malicious instructions introduced through prompt injection attempts and generates Microsoft Defender XDR alerts when attacks are detected. Integration with Microsoft Purview extends protection by auditing or blocking prompts and tool calls in real-time to help prevent exfiltration of sensitive data based on Purview policies. Advanced hunting enables security teams to investigate local agent activity, hunt for exposure risks, and correlate agent inventory with existing endpoint telemetry.</P>
<H3>Microsoft Execution Containers for local agents (Public Preview)</H3>
<P>As organizations adopt local AI agents running directly on user devices, they introduce new challenges around visibility, control, and risk, these agents often operate outside traditional governance boundaries, can access sensitive data or tools, and may execute in unmanaged environments. Microsoft Execution Container (MXC) addresses this challenge by enforcing a secure, isolated runtime for local agents, bringing them back under centralized administrative control. In public preview, MXC enables IT to require that local agents run within a hardened Windows container, reducing exposure from unmanaged execution while standardizing security protections across the fleet. By combining isolation with centralized policy enforcement, MXC gives organizations greater confidence in local agent usage, improving visibility into runtime behavior, enabling consistent governance, and mitigating the risk of data leakage or malicious activity without disrupting user productivity.</P>
<P>&nbsp;</P>
<img />
<H2>New Capabilities for Onboarding Agents and Managing the Enterprise Agent Fleet</H2>
<P>Organizations need a faster path to enterprise readiness and stronger controls for ongoing governance. Agent 365 advances both goals by simplifying agent onboarding with Agent 365 skills, expanding programmatic management through Microsoft Graph APIs, and extending Microsoft Entra ID Governance to ecosystem partner agents, helping IT manage agents with greater automation, visibility, and control at enterprise scale.</P>
<H3>Accelerate agent onboarding for builders with Agent 365 skills</H3>
<P>With Agent 365 skills, agent developers can dramatically simplify how they bring agents into Microsoft Agent 365. As outlined in the <A href="https://techcommunity.microsoft.com/blog/agent-365-blog/agent-365-skills-bring-your-agents-into-microsoft-agent-365-in-minutes/4529838" target="_blank" rel="noopener">blog post</A>, this innovation removes the friction of the traditional onboarding “last mile” where developers previously had to manually configure identity, observability, governance, and secure access to Microsoft 365 data. With Agent 365 skills, developers can now use natural language directly within their preferred coding environments to request outcomes like adding observability or integrating tools, while the platform automatically applies and validates the required configurations. By transforming a complex, multi-step setup into a guided, outcome-driven experience, Agent 365 Skills accelerates time to enterprise readiness and enables organizations to operationalize AI agents at scale, faster and with greater confidence.</P>
<P>&nbsp;</P>
<img />
<H3>Expanded Microsoft Graph API support</H3>
<P>Agent 365 continues to expand its Microsoft Graph API surface area, giving AI administrators powerful, programmatic control over the agent ecosystem. As outlined in the Agent 365 Graph API <A href="https://learn.microsoft.com/microsoft-agent-365/admin/graph-api" target="_blank" rel="noopener">documentation</A>, these APIs enable scalable, automated management of agents, moving beyond manual or UI-driven workflows to support enterprise-grade governance, reporting, and lifecycle automation.</P>
<P>At a high level, the Agent 365 Graph APIs allow administrators to:</P>
<UL>
<LI>Retrieve a complete inventory of agents across the organization</LI>
<LI>Access detailed metadata for auditing, compliance, and lifecycle management</LI>
<LI>Automate onboarding, governance workflows, and operational processes at scale</LI>
<LI>Perform management actions such as blocking, unblocking, or reassigning ownership of agents</LI>
</UL>
<P>These capabilities help IT teams integrate agent management into existing toolchains and workflows, improving visibility, consistency, and control across growing agent estates.</P>
<P>As part of this release, two foundational package management APIs: <EM>List packages</EM> and <EM>Get package details</EM> have now moved from beta to Microsoft Graph v1.0, marking an important step toward production-ready automation. Note that these package management APIs return agents. Apps and add-ins are not included in the API response. These APIs enable AI admin to:</P>
<UL>
<LI>List packages (GET /copilot/admin/catalog/packages): Retrieve a full inventory of all agents in the organization for governance and reporting</LI>
<LI>Get package details (GET /copilot/admin/catalog/packages/{id}): Access rich metadata for a specific agent, including configuration, ownership, and deployment details</LI>
</UL>
<P>In addition, we’ve introduced couple of key enhancements driven directly by customer feedback:</P>
<UL>
<LI>Expanded role-based access: Support for Global Reader and AI Reader roles enables read-only visibility into these APIs without requiring elevated admin privileges, improving delegation and operational flexibility.</LI>
<LI>Application permissions support: Customers can now call these APIs using app-only permissions, unlocking secure, unattended automation scenarios.</LI>
</UL>
<P>By bringing these APIs to Graph API V1.0, Agent 365 provides a more stable, supported foundation for building custom automation solutions such as inventory reporting, compliance checks, and lifecycle management workflows, directly on top of Microsoft Graph. This advancement reinforces Agent 365’s role as the control plane for enterprise agent governance, enabling administrators to manage agents with the same rigor, scale, and automation used for users and applications. Learn more about the Agent Package Management API <A href="https://learn.microsoft.com/microsoft-365/copilot/extensibility/api/admin-settings/package/overview" target="_blank" rel="noopener">here</A>.</P>
<H3>Microsoft Entra ID Governance for ecosystem partner agents</H3>
<P>Microsoft Entra ID Governance for agent entitlements brings proven identity governance controls to the AI workforce, enabling organizations to manage agent access with the same rigor as human users through scoped permissions, ownership accountability, and time-bound access. With the June update, support now extends to ecosystem partner agents integrated through the Agent 365 SDK, allowing enterprises to apply entitlement management consistently across both internally-developed and third-party agents. This ensures that these agents are governed through access packages, lifecycle workflows, and least-privilege principles, reducing the risk of over-provisioned agents. This delivers unified access governance at scale, helping enforce policy, maintain compliance, and provide clear ownership and accountability as agent ecosystems expand across internal and partner-built agents.</P>

<P>The June 2026 updates continue to advance Agent 365 as the control plane for enterprise agents. Agent365: The Identity-First Control Plane for Scalable AI Agents
https://techcommunity.microsoft.com/t5/agent-365-blog/agent365-the-identity-first-control-plane-for-scalable-ai-agents/ba-p/4519921
<P>As organizations move from AI experimentation to enterprise-scale adoption, AI agents are increasingly becoming persistent actors within the digital environment accessing data, invoking APIs, and executing workflows autonomously.&nbsp;</P>
<P>This shift introduces a new governance challenge:<BR /><STRONG>How do organizations ensure visibility, control and security as the number of agents scales across cloud, SaaS and endpoint environments?</STRONG></P>
<P>Microsoft Agent365 addresses this challenge by introducing a <STRONG>control plane for AI agents</STRONG>, built on Microsoft Entra, that enables organizations to manage agents using the same identity-driven approach applied to users and applications.</P>
<H2><STRONG>Why Identity Becomes Foundational for Agent Governance</STRONG></H2>
<P>In traditional enterprise systems, identity platforms were designed to manage:</P>
<UL>
<LI>Human identities</LI>
<LI>Application identities</LI>
<LI>Service principals</LI>
</UL>
<P>With the introduction of Agent365, this model expands to include <STRONG>AI agents as first-class identities</STRONG>. Each agent is assigned a unique identity in Microsoft Entra, enabling consistent authentication, authorization, and lifecycle management.&nbsp;</P>
<P>This approach allows organizations to:</P>
<UL>
<LI>Apply <STRONG>policy-based access controls</STRONG> to agents</LI>
<LI>Enforce <STRONG>least privilege access models</STRONG></LI>
<LI>Integrate agents into <STRONG>existing IAM and Zero Trust frameworks</STRONG></LI>
</UL>
<P>As highlighted in recent partner perspectives, identity is evolving from a supporting capability to a <STRONG>centralized control plane for AI governance</STRONG>.</P>
<H2><STRONG>Managing Agent Sprawl with a Unified Control Plane</STRONG></H2>
<P>As AI agents proliferate across business units, organizations often face challenges such as:</P>
<UL>
<LI>Limited visibility into deployed agents</LI>
<LI>Inconsistent ownership and lifecycle management</LI>
<LI>Over-permissioned or unmanaged access to data</LI>
<LI>Increased operational and security risks</LI>
</UL>
<P>Agent365 addresses these challenges through a unified control plane that enables organizations to:</P>
<UL>
<LI><STRONG>Discover and inventory agents</STRONG> across the environment</LI>
<LI><STRONG>Apply governance policies</STRONG> consistently</LI>
<LI><STRONG>Secure agent interactions and data access</STRONG></LI>
</UL>
<P>This aligns with Microsoft’s broader approach to enable organizations to <STRONG>observe, govern, and secure</STRONG> AI workloads at scale.</P>
<H2><STRONG>Agents as Managed Identities in Microsoft Entra</STRONG></H2>
<P>One of the core innovations of Agent365 is the introduction of <STRONG>Entra Agent ID</STRONG>, which treats agents as managed identities within the directory.&nbsp;</P>
<P>This enables organizations to manage agents using familiar identity capabilities, including:</P>
<UL>
<LI><STRONG>Conditional Access</STRONG></LI>
<LI><STRONG>Role-based and attribute-based access control (RBAC/ABAC)</STRONG></LI>
<LI><STRONG>Identity governance workflows (e.g., access reviews, lifecycle policies)</STRONG></LI>
<LI><STRONG>Audit and compliance monitoring</STRONG></LI>
</UL>
<P>By aligning agent governance with identity, organizations can extend existing security controls without introducing separate governance silos.</P>
<H2><STRONG>Architecture Overview: Identity-Centric Control Plane</STRONG></H2>
<P>Agent365 integrates across Microsoft’s security and compliance ecosystem to provide a layered governance model:</P>
<H3><STRONG>Identity Layer (Control Plane Foundation)</STRONG></H3>
<UL>
<LI>Microsoft Entra ID for Agents</LI>
<LI>Identity governance and lifecycle controls</LI>
<LI>Conditional access enforcement</LI>
</UL>
<H3><STRONG>Governance Layer</STRONG></H3>
<UL>
<LI>Centralized agent registry (inventory of agents)</LI>
<LI>Ownership and accountability tracking</LI>
<LI>Policy enforcement across agent lifecycle</LI>
</UL>
<H3><STRONG>Security and Compliance Layer</STRONG></H3>
<UL>
<LI>Microsoft Defender for threat detection and behavior monitoring</LI>
<LI>Microsoft Purview for data protection and compliance</LI>
<LI>Integration with Zero Trust architecture</LI>
</UL>
<H3><STRONG>Observability Layer</STRONG></H3>
<UL>
<LI>Unified telemetry and dashboards</LI>
<LI>Monitoring of agent activities and interactions</LI>
</UL>
<P>Agent365 brings these capabilities together into a centralized experience within Microsoft 365, enabling consistent control across heterogeneous agent ecosystems.</P>
<H2><STRONG>Extending Zero Trust Principles to AI Agents</STRONG></H2>
<P>As agents operate autonomously and interact with multiple systems, extending Zero Trust principles becomes essential.</P>
<P>Agent365 allows organizations to apply:</P>
<UL>
<LI><STRONG>Continuous verification of agent identity</STRONG></LI>
<LI><STRONG>Least privilege access enforcement</STRONG></LI>
<LI><STRONG>Real-time monitoring and anomaly detection</STRONG></LI>
</UL>
<P>This ensures that agents operate within defined boundaries, reducing the risk of unintended actions or data exposure, while enabling secure scaling of AI adoption.</P>
<H2><STRONG>Key Capabilities Supporting Identity as the Control Plane</STRONG></H2>
<P>Agent365 enables identity-driven governance through a set of core capabilities:</P>
<UL>
<LI><STRONG>Agent Registry</STRONG><BR />Provides a centralized inventory and visibility across all agents</LI>
<LI><STRONG>Access Control</STRONG><BR />Enables policy-based and conditional access through Microsoft Entra</LI>

<LI><STRONG>Cross-platform Support</STRONG><BR />Enables governance across Microsoft, open-source, and third-party agents</LI>
</UL>

<LI><STRONG>Identity &amp; access gaps</STRONG><BR />Traditional conditional access wasn’t designed for autonomous, non-human identities.</LI>
</UL>
<P>And in most enterprises, the true scale of these gaps is often underestimated.</P>
<H2><STRONG>Enabling Secure and Scalable Agentic AI</STRONG></H2>

<P>Agent365 provides a framework to:</P>
<UL>
<LI>Bring agents under a <STRONG>common governance model</STRONG></LI>
<LI>Align AI operations with <STRONG>enterprise identity architecture</STRONG></LI>
<LI>Reduce risks associated with unmanaged automation</LI>
</UL>
<P>By anchoring agents within Microsoft Entra, enterprises can leverage existing investments in identity, security and compliance to support AI at scale.</P>
<H2><STRONG>Conclusion</STRONG></H2>
<P>The transition to agentic AI introduces a new category of identity within the enterprise.</P>
<P>With Agent365, Microsoft establishes identity as the <STRONG>foundational control plane </STRONG>enabling organizations to manage AI agents as governed, auditable and secure entities.</P>

What’s New in Agent 365: May 2026
https://techcommunity.microsoft.com/t5/agent-365-blog/what-s-new-in-agent-365-may-2026/ba-p/4516340
<P><EM>By Alex Pozin, Samer Baroudi</EM></P>
<P>As we celebrate the&nbsp;<A class="lia-external-url" href="https://aka.ms/A365GAblog" target="_blank" rel="noopener">general availability of Agent 365,</A> we’re sharing a closer look at the core capabilities that help organizations adopt agents at scale, responsibly and with speed. Agent 365 is built on three core value pillars: observe, govern, and secure, designed to give IT and security teams clear visibility, consistent controls, and enterprise-grade protection across your entire agent fleet. In this series, we’ll highlight new Agent 365 features and enhancements now and over the months ahead. Let’s dive deep into all the things you can do today. &nbsp;</P>
<H2>Observe: Monitor and manage agents in real time</H2>
<H3>Agent 365 overview dashboard</H3>
<P>The Agent 365 overview dashboard is your starting point for Agent 365 in the Microsoft 365 admin center. With the overview dashboard you gain a clear, real-time view of your agents fleet by surfacing key metrics such as total registered agents, active users, growth trends, connected platforms, total runtime in hours, and emerging risk signals. At a glance, admins can understand the scale, adoption, and overall risk posture of their agent fleet, while recommended actions highlight where attention is needed most, such as reviewing pending agent requests, assigning owners to unclaimed agents, or addressing agents with exceptions (e.g. errors in conversation). Deeper analytics enable exploration of who is building agents, which platforms are gaining traction, how adoption is trending over time, and which agents are most heavily used, helping organizations move from basic visibility to informed, proactive governance as their agent ecosystem grows. As we continue to enrich the overview dashboard based on your needs, use this surface to quickly assess the scale, health, and risk posture of your agent environment, and take prioritized actions to stay in control as adoption grows.</P>
<img>An image showing the Agent 365 overview page with tile cards displaying key metrics, top actions and agent analytics.</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1064385918"></A>Registry</H3>
<P>As organizations scale their use of agents, having a single, authoritative system of record for agents becomes foundational to visibility, control, and trust. Agent 365 provides a centralized and unified registry that serves as the system of record for agents in the organization. Each agent<SUP>1</SUP>, including those built by Microsoft, your organization, or ecosystem partners, is detailed with a complete record enriched with metadata like its name, description, publisher, platform, ownership, availability and deployment status, permissions from the Microsoft Graph, data and tools access, security and compliance details, certifications, usage activity, and more, giving IT and security teams a full view and eliminating blind spots.</P>
<img><SPAN data-contrast="auto">An image displaying the Agent 365 registry, showing a list view of agents, tile cards for agent counts, and filter/search navigation elements.</SPAN></img>
<H3><A class="lia-anchor" target="_blank" name="_Toc34039003"></A>Map</H3>
<P>The agents map view provides a visual graph of the agent ecosystem, organizing agents by platform into clear clusters and surfacing agent counts so admins can quickly understand the scale and composition of their environment. As you zoom in, the map reveals individual agents and, for a selected agent, visualizes its connections to other agents, making dependencies and relationships explicit as agent usage grows across Microsoft and third-party platforms. Together, these views help IT and security teams move beyond static lists to spot patterns, understand how agents interact, and maintain visibility as their agent landscape becomes more complex.</P>
<img>An image showing the map view of all agents in the organization clustered by platform</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc603326186"></A>Agent-level activity</H3>
<P>Agent‑level activity metrics give admins operational visibility into how each agent is running and being used across the organization. Metrics such as usage sessions, engagement trends, and active users, help admins assess agent usage and validate adoption. Additionally, by correlating activity with users and policy signals, teams can quickly assess unusual behavior, exception alerts, or misconfigurations. Exportable activity data enables deeper analysis and reporting.</P>
<img><SPAN data-contrast="auto">An image showing a fictitious agent named Zava Alerting agent selected in the registry and displaying agent activity details with metrics and charts for active users, sessions and agent responses</SPAN><SPAN data-contrast="auto">.</SPAN></img>
<H2><A class="lia-anchor" target="_blank" name="_Toc713979040"></A>Registry sync (Preview)</H2>
<P>As agents are increasingly built and deployed across multiple platforms, organizations often lack a unified way to discover, inventory, and govern them. Registry sync enables AI admins to securely consent to and connect ecosystem partner agent platforms to Agent 365, bringing external agents and their metadata into the Agent 365 registry for a more unified view of your agent population. Where supported by the synced platform, you can also take agent-level governance actions directly from the Agent 365 registry, starting with agent deletion, to agents built on these platforms. The initial preview includes connections to AWS and Google Cloud, with additional partner platforms planned for future releases.&nbsp;</P>
<P><EM>Note: Salesforce Agentforce and Databricks Genie are supported as of May 20th, 2026.</EM></P>
<img>An image showing the registry sync detail view for the Amazon Bedrock connection showing options to sync, edit, and delete the connection, connection details, and a list of synced agents.</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1664103494"></A>Shadow AI detection and blocking (Preview)</H3>
<P>Local agents installed on company devices outside IT and security visibility is an emerging endpoint risk. These agents can read files, execute code, and act on a user’s behalf, enabling access to sensitive data or risky operations without touching managed cloud services. Agent 365 provides the control plane to register and manage approved agents across the environment.</P>
<P>A new Shadow AI page, enabled by Microsoft Defender and Microsoft Intune, helps identify local agent activity on Windows devices and apply endpoint controls. Initial support includes OpenClaw, with plans to expand to additional widely used agents over time. Admins get a centralized view of local agent usage and can take action to limit unsanctioned execution paths at the endpoint, helping reduce risk while supporting approved tools.</P>
<UL>
<LI>Detect — one view of local agents across the environment with Agent 365</LI>
<LI>Block — Intune policies that help stop unsanctioned agent execution at the endpoint</LI>
<LI>Protect at scale — guardrails expand with your estate as coverage extends beyond OpenClaw to GitHub Copilot CLI, Claude Code, and more.</LI>
</UL>
<P>These capabilities help reduce Shadow AI exposure and bring local agents into a governed, secure endpoint posture.</P>
<img><SPAN data-contrast="auto">An image showing the </SPAN><SPAN data-contrast="none">new Shadow AI page in Agent 365 in the Microsoft 365 admin center, with a list of devices that OpenClaw agents are running on.</SPAN></img>

<img><SPAN data-contrast="auto">An image showing the </SPAN><SPAN data-contrast="none">new </SPAN><SPAN data-contrast="none">Shadow AI </SPAN><SPAN data-contrast="none">page of Agent 365 in the Microsoft 365 admin center, where Intune policies are being applied</SPAN></img>
<H2><A class="lia-anchor" target="_blank" name="_Toc926392280"></A>Govern: Establish guardrails for agents and users</H2>
<H3><A class="lia-anchor" target="_blank" name="_Toc66579357"></A>Agent-level lifecycle and governance actions</H3>
<P>AI admins can install, publish, block, unblock, delete, assign new owner for agents - all directly from the Agent 365 registry. Centralized lifecycle and governance actions remove friction, reduce delays, and enable fast response as agents are created, shared, and retired.</P>
<img><SPAN data-contrast="auto">An image showing the agent-level governance actions in the Agent 365 registry</SPAN></img>
<H3><A class="lia-anchor" target="_blank" name="_Toc195144610"></A>Agent distribution and availability controls</H3>
<P>Agent distribution and availability controls ensure the right agents reach the right users without overexposure or risk. You can install an agent and precisely control where it’s available across the organization, choosing to make it available to no users, all users, or specific users and groups. This foundational control is critical as it can help enable safe and intentional rollout of agents aligned to roles, readiness, and business need.</P>
<img>An image displaying the Zava Alerting agent selected in the registry showing installation and availability controls, making it available to only the Agent 365 AI admin and Security Admin user groups</img>
<H3>Admin approval and publication flow for requested agents</H3>
<P>The agent approval and publication flow gives admins a centralized control point to review agents before they reach users. Assess each requested agent’s capabilities, data access, permissions, and security and compliance posture in the Agent 365 registry, then choose to publish or reject it from a single workflow. This prevents agent sprawl, reduces over‑privileged access, and ensures agents are onboarded with the right governance across Copilot Studio, Microsoft Foundry, and expanding agent platforms.</P>
<img><SPAN data-contrast="auto">An image displaying requested agents showing the fictitious Staffing Agent selected with options to either publish to store or reject submission</SPAN></img>
<H3><A class="lia-anchor" target="_blank" name="_Toc578845148"></A>Agent management rules</H3>
<P>To help scale governance as adoption grows, Agent 365 automates routine management jobs with rules that act when conditions are met such as expiring inactive agents or blocking agents flagged as risky. Initially, rules-based governance will include standard rules for auto-deployment&nbsp;of Microsoft-built agents as well as auto-reassignment of ownerless agents (starting with agents built with Agent Builder).</P>
<img>An image displaying agent management rules in Agent 365 settings displaying the standard rule for reassigning ownerless agents.</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1903669693"></A>Policy templates</H3>
<P>Policy templates address the challenge of applying consistent security, compliance, and access controls as agent adoption scales across the organization. By grouping existing policies from services like Microsoft Entra, Microsoft Purview, Microsoft Defender, and Microsoft SharePoint into reusable templates, admins can apply standardized settings and guardrails to agents during approval or onboarding. This ensures consistent governance without configuring individual policies per agent, and is distinct from rules based automation, which manages lifecycle actions after deployment.</P>
<img>An image displaying policy templates in Agent 365 settings showing a specific policy template detail view including policies from Microsoft Entra, Purview, Defender, and SharePoint</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1519144774"></A>Tools management</H3>
<P>Tools are the resources and services an agent uses to take action and get work done within approved boundaries; for example, an agent can use the Microsoft Teams MCP to schedule a meeting, summarize a conversation, and post updates back to a Teams channel for the group. As agents are built with more capabilities taking more actions across Microsoft 365 and beyond, unmanaged tools introduce security, compliance, and operational risk. Tools management in Agent 365 gives AI admins a centralized control point to view, allow, or block the tools agents can use, such as Microsoft MCP servers, across the tenant. By enforcing consistent, admin-approved tooling policies, organizations ensure agents operate only within approved boundaries and permissions, reducing risk without slowing innovation or requiring per-agent configuration.</P>
<img><SPAN data-contrast="auto">An image displaying the Tools management pane in Agent 365 displaying a list view of MCP servers</SPAN></img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1655251611"></A>Identity governance for agents</H3>
<P>High-impact agents often rely on access to a wide range of organizational resources to perform their tasks, making it critical to manage permissions with precision and control. Microsoft Entra ID Governance for agents brings agents into the same identity governance model used for people. Access packages help define and manage agent permissions with appropriate scope and control, while sponsor lifecycle workflows ensure each agent identity has an assigned user responsible for overseeing access, maintaining accountability, and keeping access aligned with organizational policies over time. Together, these capabilities help organizations keep agent access visible, intentional, and manageable as agents evolve, enabling consistent governance and control at scale as agent adoption grows.</P>
<img>An image displaying ID Governance access package policy being applied to a policy template in Agent 365</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc2131807634"></A>Data Lifecycle Management for agents and interactions</H3>
<P>As agents reason over and generate content, organizations need clear controls over how long agent interactions are retained and when they’re removed. Microsoft Purview Data Lifecycle Management enables admins to define retention and deletion policies for human‑to‑agent and agent‑to‑human interactions, scoped by users and groups, with custom retention periods and post‑retention actions. By extending proven Purview controls to agent interactions, organizations can reduce data exposure and scale agent adoption with consistent, auditable data governance.</P>
<img>An image displaying a data lifecycle management retention policy in Microsoft Purview</img>
<P>&nbsp;</P>
<H3><A class="lia-anchor" target="_blank" name="_Toc1881885847"></A>Communication compliance for agents</H3>
<P>As agents interact with people at scale, organizations need visibility and controls to detect unethical, inappropriate, or non-compliant behavior. Microsoft Purview Communication Compliance in Agent&nbsp;365 enables you to define and apply policies to human-to-agent and agent-to-human interactions, enabling centralized detection, review, and investigation of risky behavior. By bringing AI interactions into existing compliance operations, organizations can promote responsible agent use, protect employees, and scale agent adoption with built-in oversight and accountability.</P>
<img><SPAN data-contrast="auto">An image displaying a communication compliance policy in Microsoft Purview</SPAN></img>
<H3><A class="lia-anchor" target="_blank" name="_Toc358132836"></A>eDiscovery for agent activity</H3>
<P>Agents generate and act on organizational data, and legal and compliance teams need a way to preserve, search, and review agent activity with the same rigor as human communications. Purview eDiscovery lets organizations place agent interactions under legal hold, search agent‑to‑human and human‑to‑agent interactions across all agents, and review both agent outputs and the documents accessed during execution runtime, all within Microsoft Purview. This delivers a defensible, end‑to‑end discovery experience for agent activity using familiar legal and compliance workflows, enabling confident adoption while meeting regulatory and litigation obligations.</P>
<img>An image displaying an eDiscovery query in Microsoft Purview</img>
<H2><A class="lia-anchor" target="_blank" name="_Toc628245340"></A>Secure: Protect agents comprehensively</H2>
<H3><A class="lia-anchor" target="_blank" name="_Toc1175728563"></A>Risk flags in Agent 365 registry and overview</H3>
<P>Agent 365 brings IT and Security teams together to create a connected experience for governing AI agents. Agent 365 surfaces agent‑level security and compliance risk flags, powered by first‑party signals from Microsoft Defender, Entra, and Purview, giving AI admins a unified view of risky agents directly in the Microsoft 365 admin center. From the Agent 365 overview or registry, admins can take actions like block agents or restrict access, and escalate to security teams to quickly responds and reduce risk. By bringing IT and Security signals together in a single management surface, Agent 365 enables stronger cross‑team collaboration, making agent management a shared responsibility where IT and Security teams work together to assess risk, take action, and govern agents securely and at scale.</P>
<img><SPAN data-contrast="auto">An image displaying the security details for a fictitious Comms agent showing two risk flags identified by Microsoft Purview</SPAN></img>
<H3>Conditional Access for agents</H3>
<P><SPAN data-contrast="auto">Agents acting on behalf of users can introduce new access risks, especially when interacting with organizational resources. Microsoft Entra Conditional Access enforces dynamic, granular access policies for agents that operate independently, and extends existing user policies to agents acting on behalf of users. It applies the same Zero Trust principles to ensure agent actions are consistently evaluated based on real-time context and risk. This helps organizations reduce the risk of unauthorized or unsafe access by enforcing adaptive, risk-based access controls without introducing a new policy model. Note that Conditional Access for agents&nbsp;is&nbsp;generally available&nbsp;for&nbsp;delegated access agents&nbsp;(agents that act on behalf of the user) and is in public preview for own access agents (agents that operate with their own identity, not tied to a user session).</SPAN></P>
<img>An image showing the creation of a new conditional access policy for agents in Microsoft Entra admin center</img>
<P>&nbsp;</P>
<H3><A class="lia-anchor" target="_blank" name="_Toc1956793408"></A>Identity protection for agents</H3>
<P><SPAN data-contrast="auto">Agents, whether they are acting on behalf of users or operate independently, can introduce new access risks when elevated agent risk, user risk or sign-in risk is present. Microsoft Entra ID Protection prevents compromise with dynamic evaluation of agent and user identity compromise risk. These risk signals can then be used by Conditional Access policies to block or constrain access to prevent compromise with risk-based Conditional access for agents that act independently and extending risk-based conditional access from users to agents for agents that work on behalf of users. Similar to&nbsp;Conditional Access, Identity protection for agents is&nbsp;generally available&nbsp;for&nbsp;delegated access agents&nbsp;(agents that act on behalf of the user) and is in Public preview for&nbsp;own access agents&nbsp;(agents that&nbsp;operate&nbsp;with their own identity, not tied to a user session).</SPAN></P>
<img>An image displaying a Conditional Access policy for agents in the Microsoft Entra admin center</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc699769135"></A></H3>
<H3><A class="lia-anchor" target="_blank" name="_Toc1604745883"></A>Secure Access Service Edge for agents</H3>
<P><SPAN data-contrast="auto">Secure Access Service Edge (SASE) for agents extends identity-aware, network-level security controls to agent traffic. For Microsoft Copilot Studio agents&nbsp;and&nbsp;agents running on local endpoint devices&nbsp;with&nbsp;</SPAN><A href="https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-install-windows-client" target="_blank" rel="noopener"><SPAN data-contrast="none"><SPAN data-ccp-charstyle="Hyperlink">Global Secure Access client</SPAN></SPAN></A><SPAN data-contrast="auto">&nbsp;installed,&nbsp;it provides prompt injection protection, threat intelligence filtering, web and URL filtering, and network file filtering to help reduce exposure to malicious destinations and unsafe transfers</SPAN><SPAN data-contrast="auto">.</SPAN><SPAN data-contrast="auto">&nbsp;</SPAN><SPAN data-contrast="auto">Together, these capabilities help organizations extend consistent network protections to agent traffic and support safer agent adoption at scale.</SPAN></P>
<img><SPAN data-contrast="auto">An image showing Global Secure Access for agents and traffic details in Microsoft Entra</SPAN></img>
<P>&nbsp;</P>
<H2>Threat detection and blocking for agents (Preview)</H2>
<P>Agent adoption brings new threats, such as prompt attacks and tool misuse. Microsoft Defender enables security teams to detect, block, and investigate agent threats in runtime. For example, when an agent abuses its permissions to an email MCP server, exhibiting suspicious behaviors that may cause security incidents, Microsoft Defender can block the email invocation to reduce the incident's impact and trigger incident alerts in the Defender portal for investigation and response. This capability enables security teams to effectively defend agents against the evolving AI threat landscape.</P>
<img>
<P>An image showing how a security team can detect, block, and investigate agent threats such as prompt attack and tool misuse in the Microsoft Defender portal</P>
</img>
<H2>Threat hunting and investigation for agents (Preview)</H2>
<P>Beyond threat detection and blocking, security teams can use the unified observability logs in Agent 365 for Advanced Hunting to proactively search for threats, vulnerabilities, and potential exposures in their organization's agentic environment. For example, security teams can identify&nbsp;risky configurations, such as agents with MCP tools using maker credentials. These permissions allow MCP tools to operate as the maker, potentially leading to privilege escalation and exposure. Security teams can run queries in Advanced Hunting to generate a list of agents that present this risk, then collaborate across teams to remediate these risks before they turn into incidents.</P>
<img>Security team can proactively identify vulnerabilities and exposure leveraging Advanced Hunting capabilities in Microsoft Defender</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1894137746"></A>Agent security posture management (Preview)</H3>
<P>As organizations deploy more agents, security teams need continuous insight into which agents are over‑privileged, misconfigured, or exposed to attack. Microsoft Defender provides agent security posture management by assessing the security posture of Foundry and Copilot Studio agents, identifying vulnerabilities such as excessive permissions and misconfigurations, and surfacing prioritized security recommendations, risk context, and attack path analysis to AI agents. This enables teams to focus remediation where risk is highest, reduce exposure early, and ensure agents are built, deployed, and operated securely across their lifecycle.</P>
<img>An image showing the fictitious agent Zava Assist in Microsoft Defender</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc568899743"></A>Data Security Posture Management (DSPM) AI Observability for agents</H3>
<P>Organizations lack clear visibility into how AI agents access and expose sensitive data, increasing the risk of oversharing and unintended data leakage. Microsoft Purview AI Observability in DSPM provides unified visibility into all agents operating across your environment, Microsoft and non‑Microsoft, and continuously assesses agent data risk posture. This enables security teams to identify sensitive data exposure early, make informed decisions, and proactively reduce risk before it becomes an incident.</P>
<img>An image showing AI observability within Data Security Posture Management (DSPM) in Microsoft Purview</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1188330610"></A>Insider Risk Management for agents</H3>
<P><SPAN data-contrast="auto">As organizations scale AI agents, they lack visibility&nbsp;into&nbsp;whether agents are accessing, generating, or exposing sensitive data in risky ways. Microsoft Purview Insider Risk Management for agents&nbsp;evaluated&nbsp;insider risk&nbsp;for agents&nbsp;by treating&nbsp;them&nbsp;as first</SPAN>‑<SPAN data-contrast="auto">class identities, enabling detection of risky agent behaviors such as anomalous data access or sensitive content in outputs. This allows security teams to intervene early and confidently scale AI agents while maintaining security, accountability, and compliance.</SPAN></P>
<img>An image showing an alert spotting an agent attempt at sensitive file exfiltration within Microsoft Purview</img>
<H3><A class="lia-anchor" target="_blank" name="_Toc1383738578"></A>Data loss prevention for agents</H3>
<P>As agent adoption scales, confidential information can be unintentionally included in agent interactions, increasing the risk of data exposure across the organization. Microsoft Purview Data Loss Prevention (DLP) extends the same protections organizations use for people - such as to prevent data exfiltration and oversharing - to AI agents, for example by blocking an agent from emailing a confidential file to an external recipient.</P>
<P>Also, DLP controls for grounding data protect the data agents rely on to reason and respond to interactions. It leverages DLP and labeling policies directly to the data sources used for grounding, preventing agents from accessing or using sensitive content that shouldn’t inform AI decisions or outputs. This gives organizations confidence that advanced AI agents can be deployed without increasing data exposure or compliance risk, even as agents operate across multiple data systems.</P>
<img>An image displaying a conversation with fictitious agent Zava Procurement Agent showing a DLP-protected document cannot be summarized</img>
<H2><A class="lia-anchor" target="_blank" name="_Toc813205042"></A>Conclusion</H2>
<P>As agents become a core part of everyday work, organizations need a way to extend the controls they already trust, from managing people, devices, apps, and data, to managing agents. With Agent 365, Microsoft brings agents into the same, familiar identity, security, and compliance frameworks customers already rely on today. These GA capabilities lay the foundation for scaling agent adoption with confidence, enabling organizations to unlock innovation and productivity while ensuring agents remain governed, secure, and aligned with your organization's needs.</P>

<H2>What is Microsoft Agent 365?</H2>
<P>Agent 365 is the control plane for AI agents. Whether your agents are built with Copilot Studio, Windows 365 for Agents, Microsoft Foundry, open-source frameworks, or third-party platforms, Agent 365 helps you observe, secure, and govern them.</P>
<P>Agent 365 extends your existing infrastructure to AI agents—adapting the tools and protections you use for employees to meet agent-specific needs. It unites familiar but tailored systems: Microsoft 365 apps optimized for agent productivity, Microsoft Admin Center for agent management, Windows 365 for Agents for a secure execution environment for computer‑using AI agents, and Defender, Entra, and Purview for agent security and governance.</P>
<P>⭐ <STRONG>Read the <A class="lia-external-url" href="https://www.microsoft.com/microsoft-365/blog/2025/11/18/microsoft-agent-365-the-control-plane-for-ai-agents/" target="_blank" rel="noopener">announcement of Agent 365</A> on the Microsoft 365 blog.</STRONG></P>
<H2>When was Agent 365 introduced by Microsoft?</H2>
<P>Last year, we heard the IDC prediction that there will be 1.3 billion agents by 2028. With early adoption of agents, plus no-code and low-code platforms like Copilot Studio and Microsoft Foundry, the agent wave was happening—without IT management, security, or governance. To help organizations take control of agent sprawl, we introduced Microsoft Agent 365 at Microsoft Ignite on November 18, 2025. Agent 365 was detailed in an Innovation Session at the conference by Nirav Shah, CVP of Agent 365 with <a href="javascript:void(0)" data-lia-user-mentions="" data-lia-user-uid="648376" data-lia-user-login="NetaH" class="lia-mention lia-mention-user">NetaH​</a>, &nbsp;<a href="javascript:void(0)" data-lia-user-mentions="" data-lia-user-uid="2760124" data-lia-user-login="monicaugwi" class="lia-mention lia-mention-user">monicaugwi​</a> &nbsp;and Mark Luquire of EY.</P>

<H2>How do I get started with Agent 365?</H2>
<P>Get the <A class="lia-external-url" href="https://adoption.microsoft.com/copilot/frontier-program/" target="_blank" rel="noopener">Frontier preview program</A> for <STRONG>early access</STRONG> to Microsoft Agent 365. Frontier connects you directly with Microsoft’s latest AI innovations.</P>
<H5><STRONG>How to enable Agent 365 with the Frontier preview program</STRONG></H5>
<P>To start with Agent 365, sign into <A class="lia-external-url" href="https://admin.microsoft.com/" target="_blank" rel="noopener">Microsoft 365 admin center</A> &gt; select <STRONG>Copilot</STRONG> &gt; select <STRONG>Settings</STRONG> &gt; under <STRONG>User access</STRONG>, select <STRONG>Copilot Frontier</STRONG> &gt; choose the specific users, groups, or select all to grant access to the Frontier program. The tenant needs to have at least one license of Microsoft 365 Copilot to enable Microsoft Agent 365 in Frontier.</P>
<img />
<P>After you've granted users and groups access to the <STRONG>Copilot Frontier</STRONG> program, go to <STRONG>Agents</STRONG> from the left-pane inside the Microsoft 365 admin center to get started. You might be prompted to agree to the terms of service.</P>

<H2>Where can I find development resources for Agent 365?</H2>
<P>Getting started with Agent 365 traditionally requires moving through a series of setup steps—installing the <A class="lia-external-url" href="https://learn.microsoft.com/microsoft-agent-365/developer/agent-365-cli" target="_blank">Agent 365 CLI</A>, preparing prerequisites, creating an agent blueprint, deploying code, and finally publishing through the Microsoft 365 admin center. Each phase introduces its own checks and decisions, which can make the process feel complex for new builders. The AI‑guided setup streamlines that experience by letting an AI coding agent—like GitHub Copilot in VS Code—handle the lifecycle on your behalf. Instead of jumping between docs and running commands manually, you simply provide a single instruction file, and the AI guides you interactively through the entire workflow.</P>
