## Headline

What changed this week in the Agent 365 field guide

## Body

Updated this week: the Agent 365 field guide for security and compliance engineers.

Eight things moved on Microsoft Learn, and the guide moved with them:

• **Defender for Endpoint** **local agent discovery** is **generally available** on Windows and macOS. Its support matrix lists sixty-two tools on Windows and fifty-nine on macOS; the Windows Subsystem for Linux and macOS VS Code extension entries are still in preview. Most tools are listed once Defender sees the process run, and VS Code extensions are found from installed-extension data even if they never run. An entry is not proof that anyone used the tool, and the list is not a software inventory. agent-365-guide/#s5-5

• **Defender runtime protection** for local agents takes its **supported agents** from the same matrix: agent hooks for Claude Code, Claude Desktop in Code mode, GitHub Copilot CLI and app, and the VS Code extensions for GitHub Copilot and Claude Code; network inspection for tools such as ChatGPT Desktop and Ollama Desktop. **Intune's policy template** for it is GA and gains an AI agent runtime inspection setting, but the feature it configures is still in preview. agent-365-guide/#s7-4

• **Conditional Access** policies that use the **Agent risk** condition need **Entra ID P2 or Microsoft 365 E5** beside Agent 365. It is the one agent policy an E3 base plan does not cover. Policies in the Users assignment do not reach agent users, and agent users cannot be scoped by group. agent-365-guide/#s7-1

• **Connected platforms** now collect **observability** from five platforms, with Salesforce Agentforce and Databricks Genie joining Amazon Bedrock, Google Vertex AI and Anthropic. Each connection has a **Collect agent observability data** switch, a Frontier preview setting that is on by default and queries the provider's own logs, which the provider bills. Creating, syncing or deleting a connection is not guaranteed to reach the Purview audit log, so keep that trail in your change process. agent-365-guide/#s5-4

• **Connected platforms** reach each source platform from a **fixed set of outbound IP addresses**. Where the platform restricts network access, allow them before you connect. A blocked connection can fail with an **authentication error** even when the credentials are correct. agent-365-guide/#s5-4

• **Observability data** for **Foundry and Copilot Studio agents** includes **prompts and responses**. It is stored in the tenant's default geography even when the agent runs in another Azure region, and each platform has a control to stop sending it. agent-365-guide/#s5-6

• The **agent registry** can list one **Copilot Studio agent twice**: once as shared by its creator, once as published by your organisation. They are separate entries, and removing one does not remove the other. The Manage agents page that describes both entries also says Researcher and Analyst sit outside every agent setting. agent-365-guide/#s6-1

• **MCP servers** come in **three kinds**: Work IQ MCP, Microsoft-hosted workload servers kept for backward compatibility, and custom servers you register yourself. The **Agent 365 CLI** can evaluate a server before you register it. agent-365-guide/#s6-5

• Also new to the guide: chapter 10 is a **status board**. Filter the thirty-four controls by status or product, and follow each one to the section that explains it. Chapter 4 has a **map of where agents run**, and every change sits on its own page by date. agent-365-guide/#s10

Every claim in this guide links to Learn. GA/Preview status badges follow Microsoft's release notes, checked every Monday.

See what changed and what you can deploy today: https://rodneymhungu.github.io/agent-365-guide/#s10
